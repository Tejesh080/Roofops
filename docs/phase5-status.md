- **Typography:** Geist Sans / Geist Mono. Page title 30/680, project title 28/650, KPI 32/650, section 15/600, body 14, meta 12.5, labels 11.5/550 uppercase.

## Authentication

- **Login:** `/login` with `DEMO_USERNAME` / `DEMO_PASSWORD`.
  - Passwords are compared in constant time (SHA-256 then `timingSafeEqual`) and both fields are always checked.
  - Failed attempts are throttled: 5 per 10 minutes per client, with a 600 ms delay.
- **Session:** an HMAC-SHA256-signed cookie (`AUTH_SECRET` ≥ 32 characters), HttpOnly, SameSite=Lax, Secure in production, lasting 12 hours. Sign out is in the user menu.
- **Enforcement:** `proxy.ts` redirects every page to `/login` and returns 401 for `/api/*`. Every page and the copilot API *also* verify the session themselves, so access does not rely on the proxy alone.
- **Fails closed:** if any auth variable is missing or too short, nobody can sign in.
- **Headers:** X-Frame-Options DENY, CSP `frame-ancestors 'none'`, nosniff, Referrer-Policy, Permissions-Policy, HSTS, `noindex`.

## Deployment (Vercel): ready, not deployed

The Vercel CLI on this machine is logged out (`vercel whoami` → "Logged out"), and `vercel login` is an interactive browser sign-in. Everything else is prepared. To deploy:

1. `npx vercel login`
2. `cd web && npx vercel link` (new project; Root Directory `web`, framework Next.js)
3. Set these as Production environment variables, marked Sensitive. The values are in `web/.env.local`; see `web/.env.example`.
   - Required: `DASHBOARD_DATABASE_URL`, `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL`, `DEMO_USERNAME`, `DEMO_PASSWORD`, `AUTH_SECRET`.
   - Also set `DASHBOARD_DB_POOL_MAX=1`.
   - Optionally set `DASHBOARD_DB_CA_PEM` to verify the Supabase certificate.
4. `npx vercel deploy --prod`

Networking needs no change: the Supabase session pooler is public over TLS, and the web login is the least-privilege `roofops_web` role (connection limit 10). No other credential is needed or should be set on Vercel: no n8n key, no Airtable, Xero or Google tokens, and no owner database URL.

- **Client bundles:** 0 hits for the DeepSeek key, demo password, `AUTH_SECRET`, database password or pooler host.
- **Server build output:** 0 hits for the DeepSeek key, demo password and `AUTH_SECRET`. All of these are read at runtime.
- **Git:** no `.env*`, `web/.env.local`, `secrets/` or Playwright auth state is tracked. The staged diff was scanned before commit.
- **Least privilege unchanged:**
  - `roofops_web` can read the dashboard views and call `wf_invoice_prepare`, nothing else.
  - n8n's role is unchanged.
  - The copilot still has no approve/send/pay tool.

**Credential-adjacent n8n execution data (manual step).** Deleting data is not something I do on your behalf, and the n8n tools here cannot delete executions. In n8n → Roofops → Executions, delete:

## Remaining limitations

1. **Not deployed:** Vercel login is required (see above). Locally the app runs at http://127.0.0.1:3000.
2. **Single shared login:** the demo login is one shared user. It is fine for an interview, but real use would need per-person accounts (e.g. Supabase Auth or SSO).
3. **Throttling is per server instance:** login throttling is in memory. On Vercel each instance keeps its own counter, which is acceptable for a demo.
4. **Airtable webhook pings are not signature-verified.** A ping carries no data, since n8n fetches the changes with its own credential, so a forged ping can only trigger one extra read. This is a documented low risk (Phase 2).
5. **TLS to Supabase is encrypted but not certificate-verified** unless `DASHBOARD_DB_CA_PEM` is set.
6. **Scenario 01 consumes a real demo quote per live rehearsal** (9 remain), and scenario 03 is replay-only by design.
7. **Imported history is thinner than live history:** no checklists or Drive folders for imported projects, and the "Deposit"/"Progress" invoice labels are inferred from invoice dates.
